## The hard constraint — read before promising anything

**Cowork cloud sessions cannot access any GitHub repository.** Not read, not write, public or private.

- The environment has `GH_TOKEN`/`GITHUB_TOKEN`, but they are proxy-scoped and are **not valid GitHub
  credentials**. `git ls-remote` with them returns *"Invalid username or token."*
- The API error tells the agent to call `add_repo`. **That tool does not exist.** Confirmed across all
  five MCP servers after a refresh.
- No `gh` CLI. Direct `curl` to github.com is Cloudflare-blocked. Anonymous `git ls-remote` of a public
  repo works, and that is the entire extent of GitHub access.
- This is a known product gap: anthropics/claude-code issue **#84581**.
- The local-device bridge is not a workaround either: no `device_bash`, and the announced filesystem
  tools fail on a JSON-Schema dialect error before executing.

**So: build the bundle, hand it over, David pushes.** Do not tell him to attach the repo to the
session — that instruction was given once and was wrong; the affordance does not exist.

## The in-repo sweep — what replaced the Claude scheduler

`.github/workflows/inventory-sweep.yml`, Mondays 14:00 UTC plus `workflow_dispatch`. Runs
`scripts/sweep.py`, which refreshes the two purely-factual things that go stale fastest:

1. SERVIR org repository inventory, all six orgs → `data/servir-repos.json`
   *(the org API endpoints blocked from a sandbox work fine inside Actions with the built-in token)*
2. SERVIR Global App Center detail pages → `data/appcenter.json`
   *(the only source publishing an explicit status badge per service)*

It opens a PR **only on a real diff**, with `data/CHANGES.md` as the body. Quiet weeks produce nothing.
No secrets needed.

Deliberately out of scope: build matrices, NASA asset mapping, use cases — judgement, not mechanics.

**Two failure modes it is built to survive**, both verified by unit test before shipping:
- A fetch returning nothing **keeps the previous snapshot** rather than overwriting it. Without this,
  one blocked run would make the next sweep report all 79 services as brand new.
- A failed fetch **never opens a PR** — `changed` is only true for genuine differences.

Test cases run: baseline → true; identical rerun → false; new repo + status flip → true with both
changes named; total fetch failure → false, baseline intact, reported under *Attention*.
